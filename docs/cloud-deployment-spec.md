# 本次云端部署需求与验收

用户已于 2026-10-17 确认电脑和实体 Android APK 测试完成，授权把现有平台部署到其 Ubuntu 22.04、2 vCPU / 4 GiB 服务器。部署比较基线为 `28ffd1f4706eeb2e46eff77bf67875a39b05fa15`。本文件是本次新增部署脚本的 Spec；完整产品需求仍见 product-spec.md。

- 迁移既有主人账号、加密模型配置、内容、文件、技能、会话和工作区。Windows 文件绝对路径必须转换为 Linux 数据目录，文件字节和 SHA-256 不变。保留本地原件；云端不继承已有会话 token。
- 不把私人数据、密钥、服务器密码或原始聊天记录写入 Git、静态站点或安装包。原始聊天记录不迁往服务器。所有私人 API 继续验证主人身份，关闭公开注册。
- 用户提供域名后，使用 `xinxin.zhixuedu.cn` 的有效公共 HTTPS 证书并自动续期；不降低 Android TLS 验证，也不把公网 HTTP 当作可用交付。域名解析由用户在其控制台添加。
- 使用独立服务账号运行单 API/单任务 Worker，API 仅监听回环地址；静态前端和网关由独立服务账号托管。现有宝塔服务保留。
- Docker Hub 在目标网络不可达时允许使用 systemd + 独立 Python 3.12 环境。资源限制、日志轮转/保留、开机启动、失败重启、私人数据备份和恢复说明必须落地；不为了安装平台移除系统已有组件。
- 真实检查 HTTPS、登录/401、APK 跨源预检、技能检索、上传下载、Agent 工具和 SSE、权限拒绝、重启后数据恢复。云端主机执行与电脑本机执行明确区分；未测试能力不得写成已验收。
